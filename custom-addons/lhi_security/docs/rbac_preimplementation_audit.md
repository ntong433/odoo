# LHI application RBAC pre-implementation audit

This audit was completed before the RBAC refactor. It records the repository
state on 2026-08-01 and is the baseline for the migration and regression tests.
Odoo 19 uses `res.groups.privilege` plus `res.groups.privilege_id`; the native
user form renders one selection per privilege and uses the privilege placeholder
as the No Access choice.

## Cross-cutting findings

- All centralized `lhi_security` roles currently share
  `lhi_security.res_groups_privilege_lhi_erp`. Odoo 19 therefore renders them as
  one mutually exclusive selection even though they belong to different apps.
- The dashboard and sidebar are both fed by
  `lhi.dashboard.widget.get_accessible_apps()`, but that method maintains an
  independent group list, recognizes Entra-synchronized department codes as an
  authorization input, and optionally adds group-to-menu mappings.
- Empty dashboard widget `group_ids` currently means public. The module data
  records rely on this behavior, so an accidental empty restricted widget also
  becomes public.
- Application actions have no shared server-side application entitlement. Menu
  hiding therefore does not protect a direct action URL.
- Root application structure is inconsistent: several independently assignable
  apps are nested under an unprotected Operations or Programs root, while the
  dashboard targets child menus or a different native application.
- Existing company, department, project and HUB record rules are generally the
  correct row-scope boundary and must be retained while broad model ACL groups
  are replaced.
